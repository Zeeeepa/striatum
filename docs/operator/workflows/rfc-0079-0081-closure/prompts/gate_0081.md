# Gate 0081 — Conversation trajectories

Implement RFC 0081. Read `docs/rfcs/0081-conversation-trajectories.md` in full
first; it is the contract, and it captures the converged design from the
recorded two-model conversation (`docs/operator/artifacts/two-model-conversation/`).
Also read `go/pkg/reads/`, `go/pkg/rpc/registry*.go`, `contracts/daemon_methods.json`,
`go/pkg/cli/routes/`, and `go/pkg/workflowgenerate/`.

## Build (stay strictly in write scope)

1. Establish `run_event_seq` as the canonical per-run ordering primitive across
   `messages`/`events`/`artifacts`/`verdicts` (daemon-assigned at ingest; add a
   migration if a column/derivation is needed). Cover ordering with tests.
2. Add read-only daemon methods `trajectory.export` and `trajectory.watch`
   (read handlers in `go/pkg/reads/`, registered via
   `contracts/daemon_methods.json` + regenerated `registry_methods.go` /
   `routes_generated.go` using the Go `routergen` generator — run
   `go generate ./...` and keep the round-trip byte-identical). Projection is a
   READ MODEL over existing tables — add NO new authoritative trajectory table.
   Two profiles: `dialogue` (chat + artifact/publication refs) and `provenance`
   (full lifecycle). Projected rows carry only curated bodies, state labels,
   references, and content hashes — NEVER provider stdout/stderr (D028).
3. Add a narrow `trajectory_segments` table (migration) for export manifests /
   watch checkpoints only (run_id, profile, from_seq, to_seq, hash, created_at);
   it is not authority — dropping it loses no conversation content.
4. CLI: `striatum trajectory export --run-id --profile --format jsonl` and
   `striatum trajectory watch --run-id [--since <seq>]`, with a tmux-friendly
   renderer; document a tmux recipe beside `dashboard` in the daemon runbook
   section you own (or `docs/WORKFLOW_TYPES.md`).
5. Add a `conversation` workflow type + generator support (N-turn, M-model,
   alternating speaker lanes, read-inbox→reply-via-send→complete packets);
   promote `docs/operator/workflows/two-model-conversation/` as the canonical
   example; document in `docs/WORKFLOW_TYPES.md`.
6. Add a D028 guard test asserting the projection only reads curated fields.
