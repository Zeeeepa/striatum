# RFC 0082: Interrogation Sessions — Implementation Synthesis

author: implementer-claude-001
Date: 2026-05-25

## Summary

Implemented first-class **interrogation sessions**: a bounded, ordered,
peer-addressed multi-turn Q&A bound to a *live target worker session* whose
context is preserved. A reviewer can now iteratively interrogate a builder's
preserved reasoning and receive context-aware answers, in addition to reading
the published artifact. The daemon remains the single writer over
daemon-owned PostgreSQL; turns ride the existing message bus with targeting,
and surface through the RFC 0081 `dialogue` trajectory.

The acceptance bar — RFC 0082 Required Test 7, the end-to-end intention test —
passes: a builder completes an `interrogable` job, enters
`awaiting_interrogation`, a reviewer opens + asks, the builder answers from a
builder-only fact that lived only in its build packet (never re-published), the
interrogation closes, the builder session then closes, and
`trajectory export --profile dialogue` reproduces the thread.

## Data model (migration 0016, ownership-safe)

`go/pkg/db/sql/0016_interrogation_sessions.sql` adds **one new table**,
`striatumd.interrogations` (lifecycle + correlation), and bumps
`LatestDaemonDBVersion` to 16.

```
striatumd.interrogations(
  repository_id, run_id, interrogation_id,
  interrogator_session_id, target_session_id,
  topic, state CHECK (state IN ('open','closed')), turn_count,
  opened_at, closed_at,
  PRIMARY KEY (repository_id, interrogation_id))
```

Per RFC 0079 §5 and the RFC 0081 incident, the migration is a **plain new
table the runtime role can apply**: no `ALTER` of owner tables and no foreign
keys to owner-held tables (`repositories`, `runs`, `sessions`). Referential
integrity is enforced in Go; DML is `GRANT`ed to `striatumd_rw`. Required Test
9 guards this.

Turns reuse `striatumd.queue_messages` (`kind='agent_message'`,
`target_session_id` set, `payload_json.interrogation_id` + `turn` +
`turn_index` for correlation/threading) — **no `queue_messages` schema change**.

## Daemon methods

Mutations in `go/pkg/mutations/interrogation.go`, reads in
`go/pkg/reads/interrogation.go`, registered in `mutations.go` / `reads.go`, and
declared in `contracts/daemon_methods.json` (regenerated byte-stable via
`go generate ./...`). All mutations append `events` rows
(`interrogation.opened|asked|answered|closed`).

| Method | Capability | Behaviour |
|---|---|---|
| `interrogation.open` | write | interrogator-capable session opens against a **live, attested** target; fails `target_unavailable` otherwise; single-run scoped. |
| `interrogation.ask` | write | only the interrogator may ask; enqueues a question turn addressed to the target. |
| `interrogation.answer` | write | only the target session may answer; records the reply and completes the outstanding question. |
| `interrogation.close` | write | only the interrogator may close; terminal; closes the target session when it is lease-free with no other open interrogations. |
| `interrogation.list` | read | interrogations for a run. |
| `interrogation.show` | read | interrogation + ordered, curated Q&A turns. |

Capability gating: open/ask require the calling session's
`capabilities_json` to contain `interrogate`; answer requires
`session_id == target_session_id`. The methods are auto-exposed as
`interrogation.*` MCP tools via the registry (none are hidden).

## await_packet envelope (`go/pkg/mutations/claim.go`)

`HandleAwaitPacket` now returns the typed envelope and prefers a pending
question over new work:

```
{ "type": "work_packet",            ...legacy claim fields... }
{ "type": "interrogation_question", "interrogation_id": "...", "body": "...", "message_id": "..." }
{ "type": "none", "status": "no_work" }
```

Backward compatibility is preserved: the `work_packet` envelope keeps the
legacy `status`/`packet_id`/`packet`/`next_steps` keys. Plain work delivery is
unchanged for non-interrogable runs (existing claim tests stay green).
`deliverPendingInterrogationQuestion` selects the oldest pending question
addressed to the session (and to no other) and marks it delivered.

## Context-preservation window (`go/pkg/mutations/lifecycle.go`)

On `work.complete` of an `interrogable` job (flag read from the workflow
snapshot — no jobs-table column added), the builder session does **not** close:
it emits `session.awaiting_interrogation` and stays active, and the complete
result carries `interrogable: true`, `session_phase: "awaiting_interrogation"`.
`fresh_session_required` is relaxed for interrogable builders in `buildPacket`
so context survives into review. `interrogation.close` closes the target once
it holds no active lease and no other interrogation remains open.

## Trajectory + provenance (D028)

`go/pkg/reads/trajectory.go` surfaces interrogation turns in the `dialogue`
profile (agent-message branch), adding curated correlation fields
(`interrogation_id`, `turn`, `turn_index`) alongside the authored `text` —
never raw provider stdout/stderr. Required Test 8 guards that neither the
`interrogation.show` turns nor the trajectory projection carry any raw-output
field.

## CLI

`striatum interrogation {open,ask,answer,close,list,show}` wired via
`contracts/daemon_methods.json` cli_routes + param groups in
`go/pkg/cli/params/params.go`.

## Notes / follow-ups

- `go generate ./...` also regenerates `docs/architecture/DAEMON_METHOD_TABLES.md`
  (outside this job's `write_scope.allowed_paths`); it is committed with the
  contract change so the round-trip stays clean.
- Push delivery (LISTEN/NOTIFY vs MCP SSE) remains a follow-up per the RFC's
  Open Questions; V1 uses the bounded long-poll already in `await_packet`.
- The bounded idle-timeout sweep for a never-closed interrogation reuses the
  existing stale-lease recovery (RFC 0020/0077); `interrogation.close` is the
  primary close path and closes the target automatically.
