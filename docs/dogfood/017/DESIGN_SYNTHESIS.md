# Design synthesis: RFC 0021 V1 (DDD layout scaffold)

author: designer-codex-gpt-5.5-001
date: 2026-05-09

## Scope

V1 ships RFC 0021 in two landable steps (template tree + CLI
wiring). The RFC is the spec; this synthesis pins the
implementation choices not already nailed down in the RFC.

## 1. Templates

Seven `.md.tmpl` files under
`src/striatum/scaffold/templates/ddd_layout/`. Each starts with the
RFC 0021 generation comment as its first line; the body is
section-headered scaffolding the operator fills in.

| Template | Target path |
| --- | --- |
| `SPEC.md.tmpl` | `docs/SPEC.md` |
| `PRD.md.tmpl` | `docs/PRD.md` |
| `DECISION_LOG.md.tmpl` | `docs/DECISION_LOG.md` |
| `UBIQUITOUS_LANGUAGE.md.tmpl` | `docs/UBIQUITOUS_LANGUAGE.md` |
| `DDD.md.tmpl` | `docs/DDD.md` |
| `rfcs__README.md.tmpl` | `docs/rfcs/README.md` |
| `rfcs__0001-template.md.tmpl` | `docs/rfcs/0001-template.md` |

**Naming convention.** Templates that target nested paths use
`__` as the directory separator in the source filename
(setuptools package-data does not preserve subdirectories
reliably across all build backends). The scaffold maps
`__` → `/` when writing.

The two-line generation comment (first two lines of each file):

```html
<!-- Generated by `striatum init --with-ddd-layout` (RFC 0021).
     Edit freely; this file is not regenerated. -->
```

## 2. Public API

```python
# src/striatum/scaffold/__init__.py

def scaffold_ddd_layout(
    repo: Path,
    *,
    force: bool = False,
    dry_run: bool = False,
) -> dict[str, Any]:
    """Copy the ddd_layout templates into <repo>/docs/.

    Returns:
        {
          "layout": "ddd",
          "files": [
            {"path": "docs/SPEC.md", "status": "created"},
            {"path": "docs/DECISION_LOG.md", "status": "skipped",
             "reason": "exists"},
            ...
          ],
          "dry_run": False,
        }
    """
```

V1 ignores `force` (always treats existing files as `skipped`)
and ignores `dry_run` (always writes). The keyword arguments are
reserved for V1.5 to land without breaking the API surface.

## 3. CLI wiring

```python
# src/striatum/cli/parser.py — under the `init` subparser
init.add_argument(
    "--with-ddd-layout",
    action="store_true",
    help=(
        "After init, also scaffold the DDD-shaped human-facing "
        "doc layout (docs/SPEC.md, PRD.md, DECISION_LOG.md, "
        "UBIQUITOUS_LANGUAGE.md, DDD.md, rfcs/) into the target "
        "repo. Existing files are preserved. RFC 0021."
    ),
)
```

```python
# src/striatum/cli/dispatch.py — `init` branch
if getattr(args, "with_ddd_layout", False):
    from striatum.scaffold import scaffold_ddd_layout
    init_result["ddd_layout"] = scaffold_ddd_layout(repo)
```

Order of operations: `.striatum/` → skills (if `--with-skills`)
→ scaffold (if `--with-ddd-layout`). Each step's failure does
not roll back earlier steps; only `.striatum/` is mandatory.

## 5. Per-file logic

```python
for template_name, target_rel_path in TEMPLATE_MAP.items():
    target = repo / target_rel_path
    if target.exists():
        results.append({"path": str(target_rel_path),
                        "status": "skipped",
                        "reason": "exists"})
        continue
    target.parent.mkdir(parents=True, exist_ok=True)
    body = (pkg / template_name).read_text(encoding="utf-8")
    target.write_text(body, encoding="utf-8")
    results.append({"path": str(target_rel_path),
                    "status": "created"})
```

OS errors during write are caught at the per-file level:
`{"status": "error", "reason": "<message>"}`. The overall init
exit code is 1 (operational) if any scaffold file errored;
`.striatum/` initialization is unaffected.

## 8. Out of scope (V1)

- `--force` and `--dry-run` flags (deferred; API reserves them).
- Template parameter substitution (`.md.tmpl` → V1.5).
- Multiple layouts (`--ddd-layout-profile` → V1.5).
- Doctor check for missing layout (V1.5+).
- `striatum scaffold sync` upgrade verb (deferred).

## 9. Zero-regression contract

`striatum init` with no flag produces output byte-identical to
v1.7.0 — no scaffold envelope key, no scaffold files. Verified
by `test_init_without_flag_unchanged`.
