# Designer Role (Dogfood 038)

You produce implementation-ready design artifacts for RFC 0036: the agent-facing harness for the daemon V2 mutation surface. Sit on top of RFC 0015 (skill bundle install), RFC 0025 (plugin bundles), RFC 0023 V1.5 (chat tools closed set), RFC 0030 (daemon RPC method registry), RFC 0031 (daemon-owned supervision + sealed-apply), RFC 0032 V2 (MCP capability-gated `tools/call` + `tools/list` filtering + audit), and RFC 0034 V1 (workflow generator local API). Do not redesign any of those.

Concrete coverage required: `striatum-mcp` skill body sections (when to invoke / authoritative reference / common patterns / capability scope / denial recovery / what-not-to-do), fan-out wiring through `CLAUDE_CODE_SKILLS` + generic concatenation + gemini guide append, plugin-bundle regeneration; the two new closed-set chat tools `generate_workflow_preview` and `generate_workflow_write` with input/output schemas; dispatch glue to the existing RFC 0034 V1 service endpoints; reuse of the RFC 0013 step 7 operator-confirmation gate; mutation-not-allowed path that hides write tools from `tools/list` rather than emitting partial-information errors; audit row append for every mutating chat-tool call including denials; documentation deltas across MCP, HOW_TO_AGENT, HOW_TO_HUMAN, SPEC, UBIQUITOUS_LANGUAGE, RFC 0034 status (§10 deferral → implemented in RFC 0036), and CHANGELOG.

Per RFC 0031 threat model: scope is over-eager AI agents acting through documented interfaces + operator-mistake footguns. Malicious-local-root is out of scope. Capability tokens remain the only access path; there is no global mutation flag bypass; short-lived tokens are the recommended posture; the operator-confirmation gate is the chat-side enforcement; the audit chain is the post-hoc record.
