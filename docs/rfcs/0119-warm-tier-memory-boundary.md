# RFC 0119: Warm-Tier Memory Boundary and Striatum Hot Tier

Status: accepted / implemented (hot tier; D179; runtime evictor D193 deferred)
Date: 2026-06-11
author: rfc-author-claude-opus-4.8-001
Context: RFC 0044/0057 (corpus export + augmentation boundary), spec.md
§ "Corpus Export And Augmentation Boundary", the `hippo` warm-tier adjunct
(separate repo). Companion: hippo RFC 0001.

## Problem

striatum produces rich **workflow exhaust** — artifacts (decision/finding/
synthesis/ledgers/reports), lane agent-loop trajectories, and the orchestrating
operator AI's reasoning — but none of it is queryable across models or sessions.
What one lane learns is lost to the next. The exhaust either clutters the git
tree or evaporates (PTY scratch, operator transcripts). Operators rediscover the
same history; cross-model learning never compounds.

A warm-tier memory service (`hippo`/`fornix`, a separate local-first adjunct)
can turn that exhaust into queryable cross-model memory. But standing it up
brushes against two lines in `spec.md`:

1. The **Corpus Export And Augmentation Boundary** (verbatim invariants below).
2. The rule that **PTY logs are private diagnostics only** and there is **no
   durable transcript capture/export without an explicit product decision**.

This RFC authorizes the minimum boundary change to enable the warm tier and a
striatum-native **hot tier**, while *preserving* the durable-provenance model.

### The invariants this RFC must not break (verbatim, spec.md)

```
- No `import engram` or `from engram` in Striatum source.
- No `memory.*` capability in the Striatum daemon method registry.
- No state transition (`ack`, `publish-artifact`, `complete`, `verdict`,
  recovery, `run prepare`, `run start`, `corpus export`) that fails when
  an external memory consumer is missing, unreachable, or misconfigured.
```

(Generalize the first to "no `import` of any external memory consumer,"
including the warm-tier adjunct.)

## Goals

1. Authorize a default-off, redacted **lane-trajectory** feedstock class,
   exported via the pull-only `corpus export` path — never streamed.
2. Authorize a **read-only striatum-native hot tier**: a `RecallMemory`
   projection (Postgres full-text over artifacts — none exists today) and a
   **scaffold-time** digest injection into a lane worktree / bootstrap packet.
3. Authorize a narrow **eviction policy**: only explicitly allowlisted run
   exhaust may stop being committed to the git tree (moved to PG/blobs, RFC
   0072 pattern); **durable provenance stays canonical in git**.
4. Keep the warm tier strictly an **augmentation** reached only via delivered
   inert content (the `fornix` boundary).

## Non-Goals

- A `memory.*` capability in the daemon registry. The hot tier read is named
  `recall.*`/a read on existing surfaces, not `memory.*`, and it is **never** a
  retrieval call inside a transition transaction; any scaffold enrichment runs
  only after the authoritative transition commits and must fail soft.
- Any runtime dependency on the warm tier. If the adjunct is absent, everything
  works (a thinner shelf, never a wedge).
- Making the warm tier authoritative. Canonical authority is unchanged: git for
  durable provenance, PG/blobs for the rest, the Claude Code transcript store
  for operator logs.

## Design

### D1 — Three axes (resolve the durable-provenance tension)

Pin in `spec.md`: **canonical authority** (never the warm tier) · **index scope**
(everything, durable provenance included) · **eviction scope** (only run exhaust
+ unsynthesized intermediates leave the git tree). This *preserves* "repository
files are durable provenance" — only explicitly allowlisted noisy exhaust is
evictable.

### D2 — Feedstock export classes

Extend `corpus export` with one optional, default-off Striatum feedstock class:

- `lane_trajectory` — agent-loop lane trajectories, redacted and normalized
  before they enter the bundle.
- (operator-AI logs are **out of striatum's boundary** — they live in the Claude
  Code transcript store and are ingested by the warm tier directly, not via
  striatum. No striatum change needed; documented here for completeness.)

`lane_trajectory` is a **narrow supersession** of D028/D151/D154 and the
filesystem-source denial in `validateCorpusSourcePath` for this generated export
class only. The existing path guard continues to deny transcript-shaped source
paths (`transcripts`, `terminal_output`, `raw_model_output`, `transcript*.{txt,md,log}`);
`lane_trajectory` is not a generic bypass for those paths. It is generated by
the daemon's corpus-export code from approved trajectory/event sources and must
produce deterministic bytes:

1. Select rows by stable IDs and order by `(run_id, session_id, created_at,
   source_primary_key)`.
2. Normalize text to UTF-8 with replacement, LF newlines, stripped terminal
   control sequences, trimmed trailing whitespace, and explicit empty-string
   placeholders for fully redacted fields.
3. Apply the existing corpus redaction tier plus token/path/private-field
   redaction before serialization.
4. Serialize as stable-key JSONL with a schema version, source class, run/job/
   session IDs, ordinal, redaction tier, and redacted text or structured event
   fields. Raw provider stdout/stderr and token streams never appear.
5. Hash the normalized bytes in the manifest so rerunning the export over
   unchanged inputs is byte-identical except for manifest fields already
   documented as timestamp-variant.

The class remains pull-only and deterministic; an absent warm-tier consumer
changes nothing.

### D3 — Hot tier: `RecallMemory` + scaffold injection

- A **read-only** projection `RecallMemory(repository_id, query, limit)` over
  artifacts, ranked by Postgres full-text (`websearch_to_tsquery` + `ts_rank`)
  + recency + provenance weight. No pgvector, no ML in the daemon. Seam:
  `go/pkg/reads/` (new `memory.go`), feeding from the immutable artifact stream.
- A **scaffold-time** digest pass that enriches worktrees/bootstrap context only
  after the authoritative state transition has committed. `buildPacket`
  currently runs inside the claim transaction (`claim.go:229`), and
  `HandleWorktreeCreate` currently inserts the `job_worktrees` row after the
  physical `git worktree add`. The implementation must therefore keep recall
  out of those transition transactions:
  - recall reads use a separate read connection, never the claim transaction or
    the worktree-create validation/insert transaction;
  - claim state and packet delivery remain valid if recall returns an error,
    times out, or returns zero hits;
  - worktree creation records the `job_worktrees` row before any digest render,
    or otherwise makes digest-render failure non-fatal and non-orphaning;
  - digest writes occur outside the transition and fail soft to an empty shelf
    with an honest provenance header;
  - no recall result is workflow-control authority.

This is **not** a `memory.*` capability. Each digest carries an honest provenance
header naming query, source surfaces, redaction tier, timestamp, and failure
mode if the shelf is empty.

### D4 — Naming and registry

The read is `recall.*` (or a read on an existing listing surface), **not**
`memory.*`. Update `contracts/daemon_methods.json`, regenerate routes
(`go generate ./pkg/cli/routes/ ./pkg/rpc/`), add the
`docs/reference/command-authority-matrix.md` row (capability `read`,
`single_repo`), and a guardrail test asserting: absent warm tier ⇒ all state
transitions still succeed; and no `memory.*` ever enters the registry.

### D5 — Eviction allowlist

Eviction from the git tree is an explicit per-kind allowlist, never a glob. RFC
0072 blob storage can make artifact bodies portable and hash-addressed, but it
does **not** make every artifact evictable from git. For RFC 0119, the initial
allowlist is:

| Artifact kind | Eviction eligibility | Rationale |
| --- | --- | --- |
| `progress_note` | eligible after successful PG/blob persistence and manifest accounting | Run-progress notes are recoverable coordination exhaust, not final decision provenance. |

All other artifact kinds are excluded unless a later accepted decision adds
them by exact kind. The exclusions include, at minimum: `decision`, `finding`,
`findings_ledger`, `synthesis`, `handoff`, `patch_summary`, `test_report`,
`support_ledger`, `action_item_ledger`, `harness_improvement_proposal`,
`escalation`, `operator_brief`, `work_plan`, `operator_report`,
`commit_request`, `pr_request`, `auto_finalize_gate_evidence`, and
`collaboration_ledger`. Broad patterns such as `*_ledger` are forbidden.

Non-artifact scratch that was never durable provenance remains governed by its
existing scratch/retention rules; this RFC does not promote scratch to durable
state and does not authorize deleting durable provenance under the label
"exhaust."

## Acceptance

### Decision acceptance

- RFC accepted; decision **D179** recorded in `docs/decisions/decision-log.md`.
- C1-C4 from the ratification gate are discharged in this RFC text:
  - C1: recall reads use a separate connection and never the claim transaction;
  - C2: digest render cannot orphan a worktree without a `job_worktrees` row;
  - C3: git eviction uses an explicit per-kind allowlist, initially only
    `progress_note`;
  - C4: `lane_trajectory` has a narrow supersession plus deterministic
    redaction-normalization-to-bytes contract.
- No Go hot-tier implementation lands with acceptance.

### Implementation acceptance

- The three corpus invariants still hold (Go guardrails green).
- `RecallMemory` + scaffold injection landed; with the warm tier absent, the
  full suite (including state transitions) is green.
- A guardrail test proves no `memory.*` capability and no external-consumer
  import leaked into the daemon.
- Recall-failure tests prove claim and worktree-create still commit when recall
  read or digest render fails.
- Durable-provenance invariant ("repository files are durable provenance")
  preserved; only explicitly allowlisted exhaust is eviction-eligible.

## Open questions

- Whether eviction should grow beyond the initial `progress_note` allowlist.
  Any expansion requires a later accepted decision naming each artifact kind;
  globs remain forbidden.
- Whether scaffold injection should also enrich the operator bootstrap packet
  (lower-risk, human-facing) before lane worktrees. Recommended: yes, first.
