## Problem

Skills run `run_45aa8852d626879056c447fc2f17d0d9` (a `test-coverage-audit` committee) was canceled, not cleanly completed (verdict `PROCESS_UNRELIABLE`). The final review gate did not cleanly complete: `review_final_codex` was canceled and the run-recorded `review_final_agy` verdict came from an unattested no-supervisor AGY session with an `author: operator` byline. The operator had to unwind a false finish, rerun, handle no-supervisor sessions, cancel the compromised run, and synthesize/publish manually under explicit authority. See GH #240 and the retrospective.

Most of the per-JOB completion contract has already shipped (and the sub-issues are closed accordingly — see Issue disposition). Grounded reads at HEAD `f6ab9949` confirm the residual gaps all sit at the **run-completion boundary** and around **override legibility**, and together they keep the incident reproducible:

1. **Run completion gates on job STATES only.** `maybeCompleteRun` (mutations.go:841-906) flips a run to a bare `completed` when no non-terminal job remains and ≥1 job is completed, and writes `payload=nil` on `run.completed` (mutations.go:888). It never re-asserts at the run boundary that every REQUIRED artifact+verdict is present and attested. A run whose required review verdict came from an unattested session — exactly the incident — can still reach a clean `completed`.
2. **Attestation is a live probe, never frozen.** `sessionLaneAttestation` runs a live `lanehealth.Checker.Check` at call time; the `verdicts` table (0005:235-257) has `posture` but **no attestation column**; the read-side provenance category recomputes against live joins and falls back to `missing_supervisor_evidence` (artifact_provenance.go:176) if supervisor rows are reaped. Post-hoc, a run cannot prove a verdict WAS attested when recorded.
3. **Operator override is not mechanically distinct from lane output.** `HandleOverrideVerdict` records the verdict with the workflow-declared posture via `resolveReviewPosture` (review.go:266), **not** `posture='override'`. An operator override-verdict on a completed review is therefore indistinguishable from a normal lane verdict in the `verdicts` table (only `checkpoint.override` stamps `posture='override'`, operator.go:413). And no `completed_by_lanes` / `published_by_operator_override` / `completion_mode` token exists anywhere in `go/pkg/` (grep-confirmed): a run satisfied by override collapses to plain `completed`.
4. **The recovery auto-finalize verb is a second, ungated write surface for the incident class.** `finalizeAutoFinalizeCandidate` calls `recordVerdict(ctx,…,recordVerdictOptions{})` with an EMPTY options struct (recovery_auto_finalize.go:1051), so `RequireWorkSessionBackend=false` and `ensureWorkSessionBackend` (the attestation gate) is never invoked on this path. The candidate query joins only `l.state='active' AND s.state='active'` (recovery_auto_finalize.go:637-639) with no attestation/supervisor filter, so the owning session can be unattested. The only surviving gate, `enforceReviewProvenancePolicy`, returns PASS for any review that is neither `require_attested_lane` nor fresh-required. Result: a `CapabilityRecovery` caller can auto-finalize a non-fresh review with an unattested session's accepting verdict, written as `posture=neutral` with no attestation stamp — mechanically identical to a clean lane verdict. This is the incident class reachable through a different verb.
5. **A single compromised completed review job cannot be invalidated in place.** `HandleRunRetryJob` refuses a completed non-cycle-target job (run.go:519-527); the only path is whole-run `decision.record --mark-run-compromised` (operator.go:144-165) + a fresh run.
6. **Terminal run summaries are not durable.** `HandleRunSummary` is a live read (exports.go:19-95) whose friction telemetry comes from a `doctor` block whose supervisor probe **excludes terminal runs** (supervision.go:553). On a canceled/completed run — the only kind a retrospective examines — `supervisors[]` is empty and stale-lease counts decay. The retrospective had to reconstruct this by hand.

## Goals

- A REQUIRED job, and a run, can only reach a clean completed state when every required artifact+verdict is present, attempt-scoped, and — **for gates the workflow declares as requiring independent provenance** — provably attested **at record time**, by a durable stamp frozen onto the verdict, not a live re-probe and not by path existence.
- Operator/recovery output (override-verdict, checkpoint.override, review_provenance escape decision, **and recovery auto-finalize**) is **structurally incapable** of satisfying a normal lane gate; any override is recorded as `posture=override` (or an explicit `review_provenance_override` basis bound to a `decision_id`) and is enumerated, never silently equivalent to lane satisfaction.
- A run that fails the run-boundary provenance gate has a **supported resume path** to a clean terminal state — not a dead-end `needs_operator` freeze.
- A retrospective can reconstruct a run's provenance, attestation, supervisor liveness, stale leases, missing logs, and overrides from a **durable terminal record** without live daemon archaeology.
- A single compromised completed review job can be invalidated and retried without canceling the whole run, with a **durable** invalidation receipt.
- Build on shipped mechanisms (RFC 0026 attestation, RFC 0062 escalation inbox, RFC 0096 trust boundary, RFC 0027 sealed provenance, RFC 0029 recovery, RFC 0107 multi-principal) rather than reinventing them.

## Design

**Completion invariant.** A REQUIRED job may transition to completed, and a run may transition to the clean completion mode `lanes_attested`, ONLY IF every required artifact and verdict for that scope is present at the job's current attempt AND — **for each gate the workflow declares as requiring independent provenance** (`require_attested_lane=true` OR fresh/`reviewer_context_policy=fresh` per `reviewRequiresIndependentProvenance`) — the latest non-superseded accepting verdict carries a durable `lane_attestation_at_record='attested'` stamp frozen at record time (not a live re-probe) OR an explicit `review_provenance_override=true` basis bound to a `decision_id`. For all OTHER required verdict-capable gates the assertion is merely "accepting + present at current attempt" — matching the shipped admission rule, which legitimately accepts `posture=neutral` verdicts from unattested sessions on non-fresh non-required reviews. Any required gate cleared by an operator/recovery path (override-verdict, checkpoint.override, review_provenance escape decision, or recovery auto-finalize) is mechanically recorded as `posture=override` or `review_provenance_override=true` bound to a `decision_id` and can NEVER count as lane satisfaction; such a run terminates with `completion_mode='operator_override'` and the override-cleared gates enumerated in a durable `run_completion_record`.

**Scope clarification (resolves the unsoundness in a naive "attested OR override" universal predicate).** The shipped gate (`enforceReviewProvenancePolicy`, review.go:1180-1192) does NOT require attestation for a review that is neither `require_attested_lane` nor fresh-required; it returns PASS for an unattested session there. A run-boundary predicate that demanded attestation for *every* required verdict would mass-regress those legitimate runs to `needs_operator`. The invariant above therefore demands the attestation/override stamp ONLY for provenance-required gates, and demands mere presence+accepting for the rest. This scope rule is normative and must be pinned before P0-3 is cut into work.

**Already shipped (foundation — do not rebuild).** Per-call attestation gate `ensureWorkSessionBackend` (claim.go:257-297) refuses claim/complete/verdict from a session whose `lanehealth.Health.LiveTarget()` (Attested && Alive, lanehealth.go:51) is false and expires it; `enforceReviewProvenancePolicy` + `verifyReviewProvenanceDecision` (review.go:1159-1192) require an attested session OR a named accepting `escape_surface=review_provenance` decision for an accepting verdict on a fresh-required review; `review.override` and `decision.record` are `CapabilityAdmin` (so escape decisions and override-verdicts are operator-gated and NOT self-mintable by a lane session — the forged-override attack is closed at the capability layer); the markdown byline is derived from live attestation so operator/recovery output is forced to `author: operator` (artifact.go:599-631); `verifyRequiredArtifacts` is attempt-scoped (mutations.go:567-615); repo-write artifacts must be durably committed to HEAD (lifecycle.go:1142); `decision.record --mark-run-compromised` invalidates a completed run (operator.go:144-165); read-side provenance categories separate operator/recovery/auto-finalized from attested-lane (artifact_provenance.go:8-9,161-180); `checkpoint.override` already stamps `posture='override'` (operator.go:413).

**New mechanisms.**

1. *Frozen verdict provenance stamp* (P0-1). Add `verdicts` columns `lane_attestation_at_record`, `review_provenance_override`, `review_provenance_decision_id`, `supervisor_id_at_record`. The stamp is written by `applyVerdict` (the single chokepoint all verdict writes — including auto-finalize — funnel through). **The stamped attestation value MUST be the SAME probe result the admission gate used**, not a second independent `sessionLaneAttestation` call: thread the gate's attestation map from `enforceReviewProvenancePolicy`/`recordVerdict` down into `applyVerdict` and stamp THAT, so a lane that flips between the two probe points cannot stamp a value inconsistent with the gate decision. The `sessionLaneAttestation` computation (currently review.go:599, AFTER the INSERT at review.go:581) must be reordered above the INSERT — or, preferably, replaced by the threaded gate value.

2. *Override posture on all operator paths* (P0-2). `HandleOverrideVerdict` must insert `posture='override'` (literal), not `resolveReviewPosture` (review.go:266). NOTE the override-verdict path emits a `job.completed` event with `source='review.override'` (review.go:308) and a `verdict.overridden` event (review.go:340), but does NOT emit `verdict.recorded` — so the legibility assertion is against the `verdict.overridden` event and the stored row's `posture`, not a `verdict.recorded` event on this path. The P0-2 regression guard must be a **table test over EVERY `applyVerdict`/INSERT-into-verdicts caller** (recordVerdict on an attested session, named review_provenance decision, review.override, checkpoint.override, **and recovery auto-finalize**), classifying each as lane (attested-gated, may be neutral) vs operator/recovery (must stamp override or a `review_provenance_override` basis), so a NEW recovery verb that mints a verdict fails the test until it declares its posture.

3. *Recovery auto-finalize closes the bypass* (P0-2 / P0-3). `finalizeAutoFinalizeCandidate` (recovery_auto_finalize.go:1051) MUST either set `RequireWorkSessionBackend` so the attestation gate runs, OR stamp `review_provenance_override=true` bound to the auto-finalize event/decision (when `allow_no_process_execution`) so the verdict can never read back as a clean `posture=neutral` lane clear. An auto-finalized run therefore terminates as `completion_mode='operator_override'`, never `lanes_attested`. Auto-finalize already calls `maybeCompleteRun` (recovery_auto_finalize.go:1155), so the P0-3 re-verification runs for it automatically once the stamp is correct.

4. *Run-completion re-verification* (P0-3). Before `maybeCompleteRun` chooses the clean mode, iterate every REQUIRED job and assert it is completed at its current attempt, `verifyRequiredArtifacts` passes, and — per the scope rule above — for **provenance-required** verdict-capable gates the latest non-superseded verdict is accepting AND `lane_attestation_at_record='attested'` OR `review_provenance_override=true`; for other required verdict-capable gates merely accepting+present. If any provenance-required gate is unattested with no override basis, the run enters `needs_operator` (existing state, 0021) with `stop_reason='provenance_gate_failed'`, **AND writes an escalation-class blocker + `escalation_inbox` row (RFC 0062 mechanism) enumerating the failing gate ids** so `HandleEscalationResolve` (which early-returns when `len(blockers)==0`, escalation_resolve.go:49) has something to resolve. **Resume semantics:** resolving that escalation, recording the review_provenance escape decision, or P1-6 `recovery.invalidate_job` MUST re-invoke a re-verify-and-finalize step — `maybeCompleteRun` alone early-returns when `state != "running"` (mutations.go:868) and all jobs are already terminal, so flipping the run back to `running` without re-driving completion leaves it inert. The `run.completed` event payload is no longer nil: it carries the per-gate ledger (gate id → {attested|override|override_decision_id}).

5. *Terminal-state split* (P0-4). Add a `runs.completion_mode` text column (nullable) in {`lanes_attested`, `operator_override`}, keeping `state='completed'` (a new terminal STATE would force changes to `runs_state_check` (0007:5-8, 0021) and to every terminal-state filter, e.g. supervision.go:553, silently excluding override runs from terminal sweeps). `maybeCompleteRun` sets `completion_mode` from the P0-3 ledger. `run.summary` surfaces `completion_mode` + `overrides[]`. NOTE: `completion_mode` is advisory — any downstream publish/acceptance gate MUST read `completion_mode`, not just `state='completed'`; whether `operator_override` should be a hard downstream gate is an open question.

6. *Durable run_completion_record* (P1-5). On every terminal transition — **including the operator-initiated `HandleRunCancel` path (run.go:417-475, the actual incident path) and not just `maybeCompleteRun`** — snapshot a machine-readable record (per-required-job state+attempt, frozen verdict provenance, per-session attestation+close_reason, supervisor liveness class incl. `helper_detached_process_alive`, stale/expired leases, missing trajectory/pty flags, recovery events, override decision_ids), reusing the existing `artifact_provenance` category tokens (`daemon_auto_finalized_from_artifact`, `operator_published_on_behalf`, etc.). The snapshot MUST be taken in the same transaction, BEFORE `closeRemainingSessions` (mutations.go:906 / run.go:473) transitions supervisor rows, AND must read supervisor/session liveness via a path that does NOT apply the non-terminal-run filter (supervision.go:553) or strictly before the `runs.state` UPDATE flips to a terminal value — otherwise the snapshot reads the very emptiness it exists to fix. `run.summary` reads the frozen record for terminal runs and gains a `sessions[]` block (the per-session block `docs/reference/spec.md` already promises but `HandleRunSummary` does not deliver); evidence-export Markdown gains deterministic `## Sessions / ## Provenance Gate / ## Operator Overrides` sections. The live read-side artifact provenance category is deprecated-for-terminal-runs in favor of the frozen record.

7. *Per-job invalidate* (P1-6). New gated `recovery.invalidate_job` (`CapabilityRecovery`): given run_id+job_id+decision_id (accepting review_provenance decision), reopen just that job and keep the run running. The fresh attempt must itself pass the attested gate to re-complete. **Coherence fix:** `reopenJobForAttempt → resetJobToBlockedWithReason` DELETEs the job's verdict rows (`DELETE FROM striatumd.verdicts`, revision_routing.go:371), which would destroy a `superseded_by_decision_id` stamp written one step earlier. Choose ONE coherent mechanism: (a) reopen via a reset variant that PRESERVES the superseded verdict row so the invalidation stays queryable and the `run_completion_record` can cite it, OR (b) drop the supersede-stamp step and make the durable receipt a dedicated `recovery.job_invalidated` event captured into the `run_completion_record`, stating explicitly that the verdict row is deleted. Either way, a test must assert the invalidation is reconstructable from a durable row/record, not only from the events log (the live archaeology P1-5 exists to eliminate). Re-verify `recovery.go`/`revision_routing.go` line numbers at HEAD `f6ab9949` before cutting this slice (the `5940e63d..f6ab9949` delta touched `recovery.go`).

## Acceptance

- A run whose only PROVENANCE-REQUIRED review verdict has `lane_attestation_at_record='unattested'` and `review_provenance_override=false` lands in `needs_operator` (NOT `completed`), writes an escalation blocker row, and after the operator records a review_provenance escape decision + resolves, re-drives to `completion_mode='operator_override'` (NOT stuck) — verifiable with a seeded run and no live daemon (P0-3, resume path).
- A non-attested-required review with a `posture=neutral` unattested verdict reaches `completion_mode='lanes_attested'` (NO false-positive regression); an attested-required/fresh review with an unattested neutral verdict → `needs_operator` (P0-3 scope rule).
- An auto-finalized run reports `completion_mode='operator_override'` and never `lanes_attested` (P0-2/P0-3 auto-finalize fix).
- A run cleared by a `review_provenance` escape decision reports `completion_mode='operator_override'` and lists the decision_id; a fully attested run reports `lanes_attested` (P0-4).
- An override-verdict on a completed review reads back `posture='override'`; the table-test guard over every verdict-write caller asserts no accepting `posture=neutral` verdict from any operator/recovery surface (P0-2).
- A verdict's attestation basis is readable from the frozen row without a live lanehealth probe, and equals the admission-gate probe value (P0-1 TOCTOU).
- `run.summary` on an operator-CANCELED run (the incident path) returns a non-empty provenance/sessions block reflecting the last-live liveness class (today empty: supervision.go:553) (P1-5).
- A compromised completed non-cycle-target review job can be invalidated+reopened while the run stays running, and the invalidation is reconstructable from a durable row/record (P1-6).
- Regression guards: unattested submit-review still refused (review.go:1159-1192); review.override still accept/accept_with_findings only (review.go:179-181); `--mark-run-compromised` still requires an accepting outcome on a completed run.

## Open questions

- **NULL-stamp cutover — RESOLVED 2026-06-10 (operator: halbritt) → fail-closed-after-migration.** Jobs completed before the 0024 migration have no frozen stamp. The operator decision is **fail-closed**: a run that COMPLETES after the migration treats a NULL `lane_attestation_at_record` on a provenance-required gate as **unattested**, so it cannot reach `completion_mode='lanes_attested'` and instead routes to `needs_operator`/`provenance_gate_failed` with the standard operator-escape path (record a `review_provenance` escape decision → terminates as `operator_override`). Runs that already reached a terminal state before the migration are NOT retroactively invalidated, and the 0024 backfill MUST NOT synthesize an `attested` value for historical verdict rows (leave them NULL; only post-migration completions are gated on the stamp). P0-3 may be handed to an AFK agent on this basis. (Rejected: fail-open, which would keep the incident class reproducible for any run still completing against pre-migration verdict rows.)
- **`completion_mode` downstream semantics — RESOLVED 2026-06-10 (operator: halbritt) → advisory metadata.** `completion_mode='operator_override'` is a durable, enumerated label only; it does NOT block downstream consumers (publish steps or dependent runs) from consuming the run, matching #240 ask 7's "distinguish", not "block". Rationale: a human was already in the loop when the override decision was recorded, so a second mandatory acknowledgement is not required for V1. Consumers MAY read `completion_mode` to make their own policy choices, but the daemon imposes no hard gate. (Rejected for V1: a hard downstream gate requiring explicit operator acknowledgement before an override-completed run can be consumed — revisit only if override outputs are observed propagating provenance degradation in practice.)
- `run_completion_record` as a new immutable `artifact_kind` (free hash/provenance durability, RFC 0027-style) vs a `runs` JSON column (no lane-less artifact row).
- P1-6 receipt mechanism choice (preserve superseded row vs dedicated event+record) — a design call to make at implementation time.
- Descendant reaping safety (P2-7): grandchildren need a process-group/cgroup boundary or per-pid start-token identity to avoid killing pid-recycled or operator-shared processes.
